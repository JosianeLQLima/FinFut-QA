# 💰 FinFut — Projeto de QA

## 📌 Sobre o Projeto

O **FinFut** é uma aplicação de controle financeiro pessoal desenvolvida com o objetivo de ajudar o usuário a organizar suas **receitas, despesas e contas a pagar e receber** de forma simples e prática.

O projeto foi criado como um projeto de **QA (Quality Assurance)**, com foco na aplicação dos conhecimentos de testes de software adquiridos durante minha formação.

A proposta é simular um projeto real, desde o levantamento dos requisitos até o planejamento, execução e documentação dos testes.

---

## 🎯 Objetivo

O principal objetivo deste projeto é garantir a **qualidade, funcionalidade e usabilidade** da aplicação, identificando possíveis problemas antes que eles cheguem ao usuário final.

Durante o projeto serão realizados testes para verificar se as funcionalidades estão funcionando de acordo com os requisitos definidos.

---

## 💡 Problema

Muitas pessoas têm dificuldade para controlar suas finanças pessoais, principalmente quando precisam acompanhar diferentes tipos de despesas, receitas e contas com diferentes datas de vencimento.

O FinFut foi pensado para centralizar essas informações em um único lugar, facilitando o acompanhamento da vida financeira do usuário.

---

## 🚀 Solução Proposta

O FinFut permite ao usuário registrar e acompanhar suas movimentações financeiras.

Entre as principais funcionalidades planejadas estão:

* Cadastro de receitas;
* Cadastro de despesas;
* Cadastro de contas a pagar;
* Cadastro de contas a receber;
* Categorização das movimentações;
* Visualização dos lançamentos financeiros;
* Controle de valores;
* Controle de datas;
* Identificação de contas pagas e pendentes;
* Consulta e acompanhamento das movimentações financeiras.

---

## 🧪 Objetivo dos Testes

Como projeto de QA, serão realizados testes para verificar:

* Funcionamento das principais funcionalidades;
* Validação dos campos;
* Regras de negócio;
* Fluxos positivos e negativos;
* Tratamento de dados inválidos;
* Comportamento da interface;
* Usabilidade;
* Integração entre funcionalidades;
* Identificação e documentação de bugs.

---

## 🔎 Tipos de Testes

Durante o projeto serão utilizados principalmente testes manuais, incluindo:

* Testes Funcionais;
* Testes Não Funcionais;
* Testes de Interface;
* Testes de Usabilidade;
* Testes de Validação;
* Testes de Regressão;
* Testes de Cenários Positivos;
* Testes de Cenários Negativos;
* Testes Exploratório.

---

## 🛠️ Tecnologias e Ferramentas

As principais ferramentas utilizadas no projeto serão:

* **GitHub** — gerenciamento e documentação do projeto;
* **Excel** — criação e organização dos casos de teste e checklists;

### 📁 01-Requisitos

Documentação dos requisitos funcionais e não funcionais da aplicação, histórias de usuário e regras de negócio.

Documentação do planejamento dos testes, incluindo escopo, estratégia, cronograma, riscos e critérios de teste.

### 📁 03-Casos-de-Teste

Casos de teste detalhados para validar as funcionalidades da aplicação.

Registro dos defeitos encontrados durante a execução dos testes.

* ID;
* Título;
* Descrição;
* Pré-condições;
* Passos para reprodução;
* Resultado atual;
* Resultado esperado;
* Severidade;
* Prioridade;
* Evidências.

### 📁 06-Evidencias

Evidências dos testes realizados, como capturas de tela e outros registros necessários para comprovar os resultados.

### 📁 09-Matriz-Rastreabilidade

Materiais utilizados para apresentar o projeto, incluindo slides e documentação da apresentação final.
